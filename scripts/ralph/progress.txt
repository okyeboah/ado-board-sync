- The CLI (src/ado_board_sync/*.py) is the reference implementation; the desktop C# app is a port kept honest by desktop/tests/AdoBoardSync.Parity.Tests, which shells out to the real Python via desktop/tests/parity/parity_driver.py. Port the code, never the README.
- Gates: `PYTHONPATH=src python3 -m unittest discover -s tests -t .` (129 tests) and `ADO_BOARD_SYNC_PYTHON=python3 dotnet test desktop/AdoBoardSync.slnx -c Release` (Core 91, Parity 68, Desktop 109+8 live skipped). TreatWarningsAsErrors everywhere.
- Parser subtleties: DescriptionLines includes Task bullets; top-level `- ` bullets are both description lines and Bullets; leading blanks before a description are skipped; re.match anchoring via PythonCompat.MatchAtStart; line splitting via PythonCompat.SplitLines (StringReader semantics).
- Parity comparisons project both sides to an explicit canonical JSON (level/title/code/desc_lines/bullets), so C#-only additions to BacklogItem do not break parity as long as board semantics stay identical.
- Avalonia pitfalls already hit: RadioButton groups raise Click while loading (bind IsChecked two-way, no Click handler); StaticResource typos build clean (WindowLaunchTests resolves every key); horizontal StackPanel in the tree template makes the rail pan sideways (use Grid).
- The board's own vocabulary: work is Done only when committed AND its gate is green; anything only in the working tree is Partial (STATUS.md rule). This run keeps the pre-existing uncommitted tree uncommitted and stages nothing — commits are the user's call.

## ABSD-203/206-edit-save — ticket editing with live preview and atomic save

- Delivered: BacklogItem now carries DescriptionStart/DescriptionEnd (end-exclusive, SplitLines coordinates) so the editor and the splice share one coordinate system; BacklogSplicer rewrites one item's block preserving the file's EOL style, trailing newline, and the block's trailing blank separator lines (they are the gap between items, not content — the parser includes them in DescriptionLines, so preserving them also keeps later ranges valid across multi-edit saves).
- Delivered: BacklogNodeViewModel is ObservableObject with a settable Source buffer; preview/HTML/tasks/problems/Detail recompute per keystroke from the buffer via the same Core functions; IsDirty compares to OriginalSource. Raised PropertyChanged(IsDirty) is load-bearing — forgetting it silently disabled the whole save path (watch tests fail to find this class of bug).
- Delivered: MainWindowViewModel collects dirty buffers, splices last-to-first (descending DescriptionStart), saves atomically via BacklogWorkspace.SaveMarkdown (temp+rename; refuses backlog.changed_on_disk when the file moved since load), re-parses, rebuilds, preserves selection by (level, code, title).
- Delivered: Plan gate refuses Generate/Apply while unsaved (PlanViewModel.UnsavedEditsCheck, code backlog.unsaved) — a Plan is computed from the file and the file is the source of truth.
- UI: TextBox.editor.editable style (base .editor stays read-only for the HTML pane), Save button + Ctrl+S KeyBinding, unsaved chips in content header and item header.
- Proof: Core 108, Desktop 121+8 live skipped, Parity 68, CLI 129 — all green.
- Note: no natural authored markdown produces unbalanced HTML today (the converter escapes, code spans are protected), so live problem recomputation is pinned via the derived-view tests; the real audit still gates Apply from the saved file's parse.

## ABSD-204/207-csv-export — import CSV matching gen-csv byte for byte

- Delivered: Core ImportCsv.Serialize — a port of csvio.py's serialization plus the Python csv module's default dialect: minimal quoting (delimiter/quote/CR/LF only), doubled quotes, CRLF record terminator, Epics in Title 1 / Issues in Title 2, config-driven type names, converter-LF newlines inside quoted fields.
- Parity: parity_driver.py gained a `csv` mode; ImportCsvParityTests compares all backlog fixtures byte-for-byte (71 parity tests now).
- Desktop: BacklogWorkspace.WriteImportCsv (no PAT, no network), MainWindowViewModel.ExportCsvTo(path) (view model takes a path; the save-file picker lives in the view, same pattern as profile loading), "Export CSV…" quiet button in the rail bottom stack gated on HasProfile.
- Gotchas hit: the converter's list markup is <ul>\n<li>…</li>\n</ul> (LF between tags, not single-line), and a one-paragraph description carries NO quoting at all — verify against htmlfmt before writing expectations by hand.
- Proof: Core 116, Parity 71, Desktop 122+8 skipped, CLI 129 — all green.
